# Daily

**Goal:** every day, one layout for every player, one attempt each; a ranking of the day by score
and a global ranking by points, guests welcome to play but not ranked.

## Global Constraints

- Vocabulary is `CONTEXT.md`: Daily, Score, Points, Guest, Surrender. The day changes at midnight
  **Europe/Paris**, computed by PostgreSQL (`(now() AT TIME ZONE 'Europe/Paris')::date`), not by a
  time-zone crate.
- A daily game is an ordinary `game` row: same shots, propositions and socket as a game against
  the bot. The daily's layout is copied into it, so the engine and `game_service` keep working
  unchanged. Its layout stays sealed until it is solved, like any game.
- Score = seconds between the game's `created_at` and `solved_at`, plus 60 per wrong proposition.
  Points = `max(100, 1000 - floor(score / 6))`, 0 for an unsolved daily. Both are computed in SQL
  where they are ranked; mark the formula with a `ponytail:` comment (weights to refine after
  real games, e.g. a cost per shot). Shots are counted but not ranked.
- Guests may play the daily and nothing else; rankings list registered accounts only.
- API layering and checks are `CLAUDE.md`'s: new migration `0008_daily.sql`, `make prepare`,
  `make check`. Front: files ≤150 lines, i18n keys in both locales, `data-cy` hooks,
  `pnpm exec tsc --noEmit` and `pnpm exec oxlint --type-aware`.
- Built on `main` once the home page (`feat/home`) is merged: the front tasks link from `/` and
  `/play`.

### Task 1: Daily games

**Files:** `api/migrations/0008_daily.sql`, `api/src/models/game_model.rs`,
`api/src/repositories/game_repository.rs`, `api/src/repositories/daily_repository.rs`,
`api/src/services/daily_service.rs`, `api/src/services/game_service.rs`,
`api/src/errors/game_error.rs`, `api/src/dto/game_dto.rs`, `api/src/controllers/daily_controller.rs`,
`api/src/controllers/mod.rs`, `api/src/controllers/game_websocket_controller.rs`,
`api/tests/daily.rs`, `README.md`

Migration: a `daily` table (`date DATE PRIMARY KEY`, `layout JSONB NOT NULL`, `created_at`), and
on `game` a nullable `daily_date DATE REFERENCES daily (date)` with a unique index on
`(user_id, daily_date)`: one attempt per player per day, enforced by the database.

- `POST /daily/{date}/game` (any signed-in caller, guests included): today's date draws the daily
  on first sight (`engine::draw_layout`, `INSERT … ON CONFLICT DO NOTHING` then read, so two
  first callers agree); a past date needs an existing `daily` row, else 404; a future date is 404.
  It answers the caller's game for that day, creating it on the first call (201) and returning the
  same one afterwards (200) — a second attempt does not exist. Race: rely on the unique index and
  re-read.
- `GET /daily/today` (public) answers today's date, so the front never computes it.
- A daily game refuses a surrender, over HTTP and over the socket: new `GameError` variant, 409,
  "On n'abandonne pas une quotidienne".
- `GameView` gains `daily_date` (null for a game against the bot) and `wrong_propositions` (a
  count), so the front shows the timer and the penalty. `GET /games` lists daily games too.

**Done when:** `tests/daily.rs` proves two players get the same layout today (compare after
solving), a second `POST` returns the same game, a guest can start a daily, a future date and a
past date without a daily answer 404, a surrender answers 409 on HTTP and on the socket, and
`wrong_propositions` counts the wrong ones only.

### Task 2: Rankings

**Files:** `api/src/repositories/daily_repository.rs`, `api/src/services/daily_service.rs`,
`api/src/dto/daily_dto.rs`, `api/src/controllers/daily_controller.rs`, `api/tests/daily.rs`,
`README.md`

Two public routes, each answering the top 100 plus, when the caller is signed in (`Option<Identity>`),
the caller's own row even outside the top (`me`, null when unranked):

- `GET /daily/{date}/ranking`: solved daily games of that date whose `created_at` falls on that
  same Paris date, by registered players, ordered by score then `solved_at`. A row: rank, login,
  score, raw seconds, wrong propositions.
- `GET /ranking`: points summed over every solved daily of each registered player, the late ones
  included, ordered by points then login. A row: rank, login, points, dailies solved.

Equal scores or points share a rank (`RANK()`). A guest converted by signing up appears from then
on, with the games it kept.

**Done when:** tests prove the order and the shared rank, that a guest is absent from both, that a
daily played the day after counts in `/ranking` but not in that day's ranking, that a wrong
proposition adds exactly 60 to the score, that points follow the formula, and that `me` is filled
for a signed-in caller outside the top.

**Files:** `front/app/daily/page.tsx`, `front/app/daily/_components/*`,
`front/app/daily/_viewmodels/use-daily.ts`, `front/app/services/daily.ts`,
`front/app/services/games.ts`, `front/app/games/[id]/_components/game-header.tsx`,
`front/app/games/[id]/_components/daily-timer.tsx`, `front/app/games/[id]/_components/guest-save-card.tsx`,

`front/app/i18n/locales/en.ts`, `front/app/i18n/locales/fr.ts`

- `/daily` shows today's date (`GET /daily/today`), a "Play" button and, for an older day, a
  `<input type='date'>` capped at today. "Play" signs in as a guest first when there is no session
  (`guestLogin`, then `POST /daily/{date}/game`), then opens `/games/{id}`.
- On a daily game page: a live timer from `created_at` (frozen at `solved_at`), the penalty beside
  it as "+N min", no surrender button.
- A solved daily played by a guest shows a card inviting to sign up to keep the game and enter the
  ranking, linking to `/register` (the guest is converted there).
- Entry points: a "Daily" button on `/play` and a "Play today's daily" button in the home hero.

**Done when:** tsc and oxlint pass; by hand, signed out, `/` → daily → a guest game with a running
timer and no surrender; a wrong proposition shows "+1 min"; solving it shows the sign-up card.
