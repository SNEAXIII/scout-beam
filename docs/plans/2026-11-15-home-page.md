# Home page

**Goal:** `/` becomes a public page that teaches the rules with animated examples and credits the
game Scout Beam comes from; the player's games move to `/play`.

## Global Constraints

- Vocabulary is `CONTEXT.md` (Grid, Entry, Piece, Straight side, Slanted side, Shot, Beam colour,
  Draft, Proposition, Surrender). Front conventions are `CLAUDE.md`'s: files ≤150 lines,
  page-scoped components in `_components/`, every string through `useI18n()` with keys in both
  `en.ts` and `fr.ts`, `data-cy` on what a test would target, `lucide-react` icons, semantic
  Tailwind tokens; game colours come from `lib/colours.ts` (`PIECE_SWATCHES`, `BEAM_SWATCHES`).
- Front only: no API change, no new dependency. Animations are SVG plus CSS keyframes, no
  animation library, and stand still under `prefers-reduced-motion` (Tailwind `motion-safe:` /
  `motion-reduce:`).
- `/` calls no API and works signed out.
- Check with `pnpm exec tsc --noEmit` and `pnpm exec oxlint --type-aware` from `front/`.

### Task 2: Rules and credit on `/`

**Files:** `front/app/page.tsx`, `front/app/_components/landing-hero.tsx`,
`front/app/_components/rules-section.tsx`, `front/app/_components/inspiration-section.tsx`,
`front/components/shape-icon.tsx` (moved from `front/app/games/[id]/_components/shape-icon.tsx`),
`front/app/games/[id]/_components/*` (import path only), `front/app/layout.tsx`,
`front/app/i18n/locales/en.ts`, `front/app/i18n/locales/fr.ts`

A public page with three parts, i18n block `landing`:

- **Hero**: the name, one sentence on the game, a "Play" button to `/play` (`data-cy='play-cta'`)
  and a "Sign in" link to `/login`. The language switcher sits in a corner, as on `/login`.
- **Rules**, in this order, each a short paragraph: the 10×8 grid and its 36 entries; the five
  pieces (Square, Bar, Spike, Corner, Diamond), each with a colour, red, blue and yellow always
  present; a shot answers an exit entry and a beam colour; a straight side sends the beam back
  (180°), a slanted side turns it by 90°; the beam colour mixes what it touched (red + blue =
  violet, red + yellow = orange, blue + yellow = green, all three = black, only white = white,
  nothing = no colour); the draft, and a proposition that is correct when it gives the same
  result as the hidden layout on all 36 entries; surrender reveals the layout. Show the five
  pieces with `ShapeIcon`, which moves to `front/components/` since two pages now use it.
- **Inspiration**: "Inspired by *Orapa Mine*, by Junghee Choi and Wanjin Gill (Playte, 2024;
  published in France by Miraludo)", linking to
  `https://boardgamegeek.com/boardgame/424152/orapa-mine` (`target='_blank'`,
  `rel='noopener noreferrer'`). Check the link opens the right game before committing.

Update `metadata.description` in `layout.tsx`: the game is no longer only solo.

**Done when:** signed out, `/` renders the three parts in both languages without any request to
the API (network tab), and `Play` reaches `/play` (or `/login` when signed out).

### Task 3: Animated examples

**Files:** `front/app/_components/beam-demo.tsx`, `front/app/_components/colour-mix-demo.tsx`,
`front/app/_components/rules-section.tsx`, `front/app/ui/global.css`

Three animations placed in the rules section next to the paragraph they illustrate:

- **Beam demo**: a small grid with two or three pieces drawn like the game draws them
  (`pieceCells`, `cellPoints`, `PIECE_SWATCHES`). A beam enters from an entry, hits a slanted side
  and turns 90°, hits a straight side and turns back, and leaves; it is drawn with an animated
  `stroke-dashoffset`, its colour switching to the mix after each bounce, and the exit is marked
  with the final beam colour. The layout and the path are hand-authored constants: check each
  bounce by hand against the rules (the engine lives in the API), and keep the pieces apart as a
  real layout must.
- **Colour mix demo**: red, blue and yellow swatches joining pairwise then all three, each pair
  showing its mix from `BEAM_SWATCHES`, looping.
- **Pieces**: the five `ShapeIcon` appear one after the other (staggered fade and scale).

Keyframes go in `global.css`; every animation is wrapped so `prefers-reduced-motion: reduce`
shows the final frame, still. Each SVG has a `role='img'` and an i18n `aria-label`.

**Done when:** the three animations play on `/`, and with "reduce motion" on in the OS (or the
browser's emulation) they show their final state without moving.
